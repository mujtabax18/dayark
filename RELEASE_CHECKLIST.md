# DayArk v0.0.39 — release and open-source checklist

## Before the first public source push

- [ ] Back up my original private project and Android signing keys to safe locations.
- [ ] Use the cleaned source ZIP, **not** the original uploaded archive with `.jks` and `key.properties` files.
- [ ] Audit current and historic tracked Git files for secrets and personal data; rewrite compromised Git history if required.
- [ ] Review `LICENSE` (MIT) and third-party icon, font, image, copied source, native packaging, and content rights.
- [ ] Check `git ls-files` confirms NO keystore, password properties, local paths, Flutter build artifacts, APK/AppImage or Windows installer is tracked.
- [ ] Keep existing Android app ID, signing certificate and Windows installer AppId stable for upgrade compatibility.
- [ ] Confirm README and contribution guidelines reflect my intent.

## Test local source

- [ ] Install compatible Flutter SDK (currently pinned `3.47.9` in `.fvmrc`).
- [ ] Run `flutter doctor`, `flutter pub get`, `flutter analyze`, `flutter test`.
- [ ] Run `node lib/qa/test_life_constellation.cjs` and applicable Python `lib/qa` scripts.
- [ ] Run actual Android debug and release smoke tests with local private signing files; verify APK signature.
- [ ] Build and test Linux AppImage (with appimagetool) and Windows Inno Setup installer (with ISCC.exe).
- [ ] Test update from v0.0.38 **without uninstalling**, verify app data, encrypted backup/restore, old-format restore and LAN sync compatibility.

## GitHub and release automation

- [ ] Push sanitized repository and scripts to `main` (or my default branch).
- [ ] Enable Actions and allow repository Actions workflow to write release contents if needed.
- [ ] Open Actions → Build DayArk draft release → Run workflow.
- [ ] Enter `v0.0.39`, choose Linux/Windows/both; leave Android disabled until signing secrets are configured and approved.
- [ ] If Android should build on GitHub, use the two encrypted secrets described in `docs/RELEASE_AUTOMATION.md`.
- [ ] Check action logs for build errors and verify release still shows **Draft**.
- [ ] Download each release file, validate SHA-256, install on actual devices and confirm its version.
- [ ] Confirm the **correct in-app update assets** are attached: `DayArk.apk`, `DayArk-x86_64.AppImage`, `DayArk-Setup-windows-x64.exe`.
- [ ] Confirm GitHub autogenerated source archives contain the complete public source.
- [ ] Only then manually **Publish release**.
